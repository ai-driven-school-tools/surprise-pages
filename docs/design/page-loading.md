# ページを開いた瞬間の表示

リンクを押してから本文が出るまでの待ちを、**配信時の差し込みだけ**で縮める。保存済みの本文は変えない。

## 何が遅かったか（2026-10-01 の計測）

サーバーではなく、本文を描く前にブラウザが待たされる読み込みが主因だった。

| 場所 | 実測 |
| --- | --- |
| 配信網の静的な応答 | 約 20ms |
| 公開ページ（配信網の控えに当たる） | 約 40ms |
| 社内ページのサーバー応答 | 110〜250ms（初回 300〜480ms） |
| 見た目の指定を作る道具（Tailwind） | 展開後 398KB・読んで実行するまで描画が止まる |
| 書体の指定（Google Fonts の CSS） | 展開後 448KB・届くまで描画が止まる |
| コメント機能の部品 | 展開後 3.4MB・通信量 845KB。`defer` だが先読みで回線を取り合う |

## いまの差し込み

1. **見た目の指定を先に作る**（`src/lib/first-paint/delivery.ts`）。版の目印ごとにサーバーで作って控え、
   道具の script があった場所に `<style>` として置く。道具本体はそのあとで読む（消さない）。
2. **書体の指定で描画を止めない**（`src/lib/first-paint/first-paint.ts` の `withNonBlockingFonts`）。
   `display=swap` と書いてあるものだけ。入れ替わりは今も起きているので、見え方の約束は変わらない。
3. **コメント機能の部品を head と応答の頭で先読みしない**（`src/lib/pages/content.ts` の `scriptPreloadSrcs`）。入口が最初に必ず読む部品だけは、
   入口のすぐ前（body の末尾）で入口と同時に頼ませる（`modulepreload`・`docs/design/app-speed.md` の「道具箱の部品を分ける」）。
   本文を描くための読み込みはそれより前に見つかるので、取り合わない。

手を出さないもの: スライド・動画・個人用の配布版・過去の版・設定を値だけで読めないページ。
どれも今までどおり配る（遅いだけで、見た目は変わらない）。作るのに失敗したときも同じ。

## 見た目が変わらないことの確かめ

実在の記事 3 枚を、幅 1440px / 390px・明暗の 12 通りで、直す前後の全画面を画素単位で見比べて一致。
道具本体が届く前（先に作った指定だけ）の状態でも同じ比較を行う。

## 部品を先に描く（2026-10-11）

本文は先に出るようになったが、道具箱（コメント機能の部品）が後から足す部品が、届いた瞬間に本文を押して動かしていた。
録音の議事録では 3 回動く:

| 部品 | 動き |
| --- | --- |
| 上端の現在地の行 | 本文が 44px 下がる |
| 清書の目次（左） | 本文が右へ 304px ずれ、幅も変わる（狭い画面では上端の帯で 67px 下がる） |
| 題の下の「録音の情報」 | 題より下が 1 行ぶん下がる（録音の窓口の答えを待つので、いちばん遅い） |

実測（Chromium・4G 相当・処理 4 倍遅い・清書 9 章）: 本文は 0.06〜0.12 秒で出るのに、目次はその 0.23〜0.4 秒後に出て、
その瞬間に画面のずれ（layout-shift）0.20。

いまは配信のときに（`src/lib/first-paint/chrome.ts`）:

1. **部品が取る場所を先に空ける**（`<style data-sp-first-paint="chrome">`）。上の余白・左の余白・本文の幅・章の間の余白・旧目次を隠す指定を、
   道具箱が書くのと同じ値で書く。左の目次か上端の帯かは、道具箱と同じ判断を画面の大きさの条件にしたもの（高さの条件は章の題の折り返しを見積もる）。
   道具箱が見る高さは、見えている高さではなく**組みの高さ（`100lvh`・ツールバーを畳んだときの高さ）**。iPad の Safari は上へ戻すたびに
   ツールバーを出して見えている高さだけを縮めるので、見えている高さで決めるとスクロールのたびに左の目次と上端の帯が入れ替わる
   （`tests/checks/browser/reading-scroll.mjs` が見る）。ツールバーが畳まれない画面では 2 つは同じ値。
2. **目次と「録音の情報」は、同じ見た目・同じ場所の写しを宣言型の Shadow DOM で描く**。目次の組み方は道具箱の `readOutline` をサーバーの木で読み直したもの。
   「録音の情報」は題の下の余白が class（`mb-数字`）から読めるときだけ。
3. 道具箱は、本物を置く**同じ処理の中で**空けた指定と写しを外す（`src/widget/reading/first-paint-chrome.ts`・`mountReadingNavigation`・`mountAbout`）。
   間に描画が挟まらないので、入れ替わりは目に見えない。

同じ本文を読んだ結果はサーバーのメモリに控える（224KB の本文で初回 11ms・2 回目から 0.7ms）。
写しの字は道具箱と同じ言語（cookie の写し）で書く。社内ページの照合の印は言語で分けないので、言語を切り替えた直後の 1 回だけ、
道具箱が届くまで目次の見出しの字が前の言語のまま出ることがある。公開ページは誰にでも同じ紙を配るので既定の言語で書く。

効果（同じ条件）: 目次は本文と同じ描画で出て、画面のずれは 0。

確かめ: `tests/checks/check-first-paint-chrome.mjs`（目次の組み方が道具箱と同じ・本文を変えない・焼き付きを断る）。
この版では機能の台帳（`src/lib/settings/features.ts` の `first-paint`）で出していないので、本物のブラウザで位置のずれを測る検査は持たない。
