# 多言語対応（画面の言語）

画面の文言を言語ごとの辞書から引く仕組み。言語は **日本語（既定・正本）と英語**。
アプリの画面・本文ページの道具箱・窓口の断り文・デスクトップアプリまで、画面に出る文はすべて辞書から引く。

## 全体の形

| 役目 | 置き場所 |
| --- | --- |
| 言語の一覧・決め方・cookie の名前（純関数） | `src/lib/i18n/locales.ts`（`LOCALES`・`resolveLocale`・`negotiateLocale`・`requestLocaleFrom`・`LOCALE_COOKIE`） |
| 辞書（正本は日本語） | `src/lib/i18n/messages/ja/<分野>.ts`・`en/<分野>.ts`（束ねは `ja.ts`・`en.ts`。形は `types.ts` が日本語から導く） |
| 引く関数 | `src/lib/i18n/translate.ts`（`translator(locale, messages)` → `t(key, params)`） |
| 日付と数の書式 | `src/lib/i18n/format.ts`（時刻帯は `Asia/Tokyo` 固定） |
| サーバーの画面の言語 | `src/lib/i18n/server.ts`（`currentLocale`・`serverTranslate`） |
| 窓口の断り文の言語 | `src/lib/i18n/request.ts`（`rt`・`requestTranslate`。入口の外枠 `routeLog` が要求ごとに置く） |
| 利用者に届く例外・保存された文 | `src/lib/i18n/errors.ts`（`LocalizedError`・`localizedMessage`・`localizeStored`） |
| 画面（ブラウザ側）への受け渡し | `src/app/_components/i18n.tsx`（`I18nProvider`・`useT`・`useLocale`） |
| 本文ページの道具箱 | `src/widget/shared/i18n.ts`（`t`・`widgetLocale`） |
| 日本語だけを引く関数 | `src/lib/i18n/default.ts`（外枠の外の画面・例外の `message`） |
| 個人設定の保存先 | `workspace_preferences.locale`（空は「自動」） |
| 文言の網（検査） | `scripts/i18n/net.mjs`（`tests/checks/check-i18n.mjs` と `node scripts/i18n/leftovers.mjs` が同じものを通す） |

ライブラリ（next-intl など）は使っていない。同じ辞書を Next のサーバー・React の画面・esbuild で束ねる
道具箱・Electron の 4 か所から読むため。訳し漏れは型で止める（`en/<分野>.ts` は日本語から導いた型を `satisfies`）。

## 言語の決め方

URL には言語を載せない（`/internal/`・`/public/`・共有のリンクを動かさないため）。決め方は 1 通り:

1. 個人設定の「言語」が日本語か English ならそれ
2. 「自動」ならブラウザの言語（`Accept-Language`。q の強い順・地域つきは言語で照らす・対応外は日本語）
3. どれも合わなければ日本語

**正本は DB（`workspace_preferences.locale`）、写しは cookie `sp-locale`。**
外枠（`src/app/_components/i18n.tsx`）は画面を描くたびに、決まった言語を cookie へ書き写す（HttpOnly にしない・`Path=/`・1 年）。
別の端末で設定を変えた分も、外枠を開けば揃う。DB を引かない場所は、この写しを読む。

| どこ | 読むもの |
| --- | --- |
| 外枠と画面（`currentLocale`） | 会社の人は DB の設定 → `Accept-Language`。それ以外は cookie → `Accept-Language` |
| 窓口の断り文（`rt`） | cookie → `Accept-Language`（`routeLog` が要求ごとに 1 度決める。DB は引かない） |
| 関所（`src/proxy.ts`） | 要求の cookie → `Accept-Language` |
| 本文ページの道具箱 | cookie だけ。無ければ日本語（描く前に同期で決めるので、切り替わりも HTML の変更も無い） |

道具箱がブラウザの言語（navigator）を見ないのは、外枠・窓口と材料をそろえるため。ログインした人は必ず外枠を通るので写しがある。
社外の人が門なし公開のページだけを開いたときは写しが無く、道具箱は日本語で出る。

`src/app/global-error.tsx` は外枠の外なので、日本語の辞書を引く。

## 文言の足し方

1. `src/lib/i18n/messages/ja/<分野>.ts` に鍵と日本語を足す。鍵は「どこの・何か」（`settings.appearance.title`）。
2. `en/<分野>.ts` に同じ鍵で訳を足す（欠けると `tsc` が落ちる）。
3. 引く。

   | 場所 | 書き方 |
   | --- | --- |
   | サーバーの画面 | `const t = await serverTranslate();` |
   | ブラウザ側の画面 | `const t = useT();` |
   | 窓口 | `jsonError(rt("server.xxx"), 400)` |
   | 道具箱 | `import { t } from "./i18n";` |
   | 利用者に届く例外 | `throw new LocalizedError("<鍵>", params)` で投げ、出す所で `localizedMessage(error, t)` |

4. 差し込みは `{name}`。数で形が変わる文は `{ one, other }` にして `{count}` を渡す（日本語は 2 つとも同じ字）。
   数は言語の書式（桁の区切り）で差し込まれる。
5. 字を継ぎ足して文を作らない（`` `${title}を${on ? "オン" : "オフ"}に` `` は語順が言語で違う）。1 文ずつ鍵にする。
6. 保存先に日本語で残る文（版の要約・書き手「共同編集」・処理の失敗文）は保存の形を変えない。
   出すときに `localizeStored(text, t)` で訳す（辞書の日本語と完全一致したものだけ）。

日付と数は `src/lib/i18n/format.ts` を通す。`toLocaleString()` を言語の指定なしで呼ばない（サーバーとブラウザで字が食い違う）。

英訳の決まり: 短い自然な英語、文頭だけ大文字、ボタンは動詞 1〜2 語、絵文字なし。**「token」という語を使わない**（人に見せない決まり）。
製品・サービスの名前は訳さない。英語が長くなっても文字の目盛りを縮めない（DESIGN.md の「言葉」）。

## 組織の名前の差し込み

画面の「会社」「社内」は `{organization}`（要求の組織の名前）で言う。引く関数を作るときに 1 度だけ渡すので、呼ぶ側は渡さない
（外枠・`serverTranslate`・道具箱は配信時の札 `data-organization-name`）。名前が分からないところ（窓口の断り文 `rt`・デスクトップ）では
辞書の一般語「この組織」が入るので、そこへ届く文には差し込みを使わず「組織の中だけ」「組織の外」と書く。
英語は所有格を避ける（`Files — {organization}`）。網は `check-i18n.mjs` の 6 節と `node scripts/i18n/leftovers.mjs --organization`。

## 言語の足し方

1. `LOCALES` に足す（`src/lib/i18n/locales.ts`）。`LOCALE_NAMES` にはその言語自身で名前を書く。
2. `src/lib/i18n/messages/<言語>/<分野>.ts` を全分野ぶん `satisfies Messages["<分野>"]` で作り、束ねと `messages/index.ts` に載せる。
3. `workspace_preferences.locale` の縛りに値を足す移行を作る（`pnpm db:new`。値を広げるだけなので「足す」）。
4. `tests/checks/check-i18n.mjs` が全言語の鍵・差し込み・空の訳を見る。

## 訳さないもの

文言の網（`scripts/i18n/net.mjs`）は `src/app/`・`src/widget/`・`src/lib/` の全部を見る。訳さないものには印で理由を書く。
- ファイルごと: 先頭 15 行のコメントに `i18n-keep-file: <理由>`
- 行ごと: その行のコメントに `i18n-keep: <理由>`

理由の無い印は落ちる。印の数は上限（`KEEP_FILE_CEILING`・`KEEP_LINE_CEILING`）より増やさない。

印で残すもの:
- **保存済みページに貼る実行部**。中の文は本文の一部で、ハッシュの台帳で照合される。
  - 対象: `src/templates/deck.html`・`src/deck-design/*`と、それらに束ねられる lib の文
  - `pnpm build:deck-design` のあとも `src/templates/` と `src/lib/**/*.generated.*` が変わらないこと
- **保存済みのボタンを字面で探す箇所**（「プレゼンを始める」）
- **原稿として入る文**: スライドの見本の中身・新規作成の雛形の本文・Markdown の書き出しの見出し
- **画面に届かない文**
  - ログ・AI への依頼文・機能台帳の `purpose`
  - 内部専用の失敗（利用者には固定の 500 の文しか出ない）
- **日本語の入力を見る正規表現**・並べ替えの `localeCompare(…, "ja")`・言語の名前
- **利用者が書いた本文と題名・コメント**（`<html lang>` も本文の側が決める）

## テスト

- 既存の e2e とブラウザの検査は日本語の画面を前提にしている。
  - `playwright*.config.ts` は `locale: "ja-JP"` に固定する
  - jsdom の検査は cookie が無いので、道具箱は日本語で動く
  - デスクトップの e2e は `SURPRISE_DESKTOP_TEST_LOCALE=ja` で起動する
- 英語の画面は `tests/e2e/english.spec.mjs` が見る。
  - 英語のブラウザで開くとワークスペースが英語で、`<html lang="en">` になる
  - 個人設定で切り替わり、cookie の写しが揃う
  - 404 と道具箱が英語になる
  - `/api/v1` の断り文が `Accept-Language` に従う
- 文言を字面で見ていた検査表は、辞書の鍵で見るように直してある。検査を弱めて通さない。
