# デザイン規則

この文書は、Pages に投稿するすべてのスキル（呼び出し側）から読まれる。
ここに書いてあることは**上位ルール**で、各スキルが持つ個別のパターン集の記述より優先する。
「色の使い方」と「線と箱の使い方」は、すべての図に共通してかかる。

**額縁（色の値・書体・絵記号の読み込み）は Pages の画面にそろえる**（画面の決まりの正本は `<リポジトリ>/DESIGN.md`、
墨と地の値は `<リポジトリ>/src/lib/settings/brand.ts`）。墨・地・灰・成功と危険の色の値、色の 3 層、書体の並び、
絵記号の決まりは Pages の画面と同じ。**違うのは 1 点だけ**——画面は意味の色を 8px 以下の点にしか置かないが、
読み物の額縁は字の 1 語と、その字に添える 16px 以下の絵記号にも置いてよい（主要の青 `ads-accent` は画面の「点の青」と
同じ値だが、使い道は額縁だけのもの）。額縁の値を変えるときは、画面の正本を先に直す。

```
ベース     90%   地・字・線。無彩色の名前（ads-bg / surface / border / text / body / muted / line）だけ
アクセント  8%   リンク・フォーカス・押せるものに指を乗せたとき。額縁が持つので本文では書かない
シグナル    2%   意味の色（ads-accent / positive / negative）。8px 以下の点・1px の線と、字の 1 語・その字に添える 16px 以下の絵記号（ここだけ額縁の例外）
```

## 色の使い方

- **色は名前でしか書かない。生の色名（`slate` `blue` `emerald` `white` など）を本文に書かない。**
 名前の値は額縁が明暗 2 組で持っていて、読む人の設定に合ったほうが入る。だから本文に
 `dark:` を 1 つも書かなくてよい——逆に書き始めると、書いた 1 か所を暗い側で確かめられないまま出すことになる
- **名前は 11 個だけ**

| 役どころ | 名前 |
| :--- | :--- |
| 面 | `ads-bg`（地）/ `ads-surface`（図のまとまり・引用）/ `ads-surface-2`（チップの地・もう 1 段重ねる面）/ `ads-border`（1px の線） |
| 読む字 | `ads-text`（見出し・結論）/ `ads-body`（地の文）/ `ads-muted`（補足・図のラベル・注記・出典） |
| 読まない印 | `ads-line`（図の矢印・経路・記号） |
| 意味 | `ads-accent`（主要）/ `ads-positive`（成功）/ `ads-negative`（危険） |

- **地の文に色を書かない** — 濃さは額縁が持っている。`ads-body` を書くのは、面の中で
 濃さを変えたあと地の文へ戻すときだけ
- **`ads-line` を字に使わない** — あれは矢印と経路の色で、読ませる濃さではない。
 注記・出典・キャプションは `ads-muted`。読ませない大きい数字（連番の目印）だけは
 `text-ads-border` を使ってよい——あれは「読ませない」ための色
- **意味の色は、字の 1 語（大見出しの 1 語・結論の 1 か所）と、その字に添える絵記号と、8px 以下の点と、1px の線だけ** — 小さい字（14px 以下）と
 面（塗り）には使わない。塗った面の上に白い字を置くと、暗い側で 2.5 : 1 まで落ちる。
 チップは無彩色（`bg-ads-surface-2`）にして、色は文字とアイコンに持たせる
- **橙（注意）は無い** — 使いどころが最も少なく、明暗で色相が動き、しかも赤と橙は
 色覚特性のある人には同じ色に見える。「注意」は色ではなく語で示す
- **1 つの色 = 1 つの意味** — 同じページの中で、同じ色が 2 つの意味を持ってはいけない。橙を「3 番目のステップ」と「中程度の危険」の両方に使わない。意味のない色が 1 つ混ざるだけで、意味のある色が読めなくなる
- **色で順番を作らない** — 順番は数字と上から下（左から右）の位置で示す。色相に順序は無く、青 → 紫 → 緑を 1 → 2 → 3 と読める人はいない
- **色で分類を作らない** — 並列に並ぶものは同じ見た目にする。1 つずつ違う色にすると「この 3 つには性質の差がある」という嘘の合図になる。**並列の要素とは、節の見出し・ステップ・連番・カードのように「同じ層で横に並ぶもの」全部**を指す。「よくある誤解」の節だけ見出しを赤にする、のようなことをしない。見出しはページの構造を示すもので、その節の内容の性質を示すものではない
- **色の面積の上限** — 色を置いてよいのは 8px 以下の点と 1px の線（ここまでは画面と同じ）、それに額縁だけの例外として字の 1 語と、その字と同じ大きさ（16px 以下・`w-4 h-4`）の絵記号まで。ピル・チップは無彩色（`bg-ads-surface-2`）。カード全面の淡い塗り（`bg-*-50`、`bg-*-500/10` の全面がけ）と 4px の色付き縦帯（`border-l-4 border-*-500`）は使わない
- **色を消しても意味が通ること** — PDF の白黒印刷でも色覚の違いでも、色は必ず失われる。色は文字と記号の冗長な補助にすぎない
- **色は「減らすもの」ではなく「3 枠に集中させるもの」** — 1 ページに色の焦点を最低 2 つは置く。①冒頭の見出しの中の 1 語 ②最も重要な結論 1 か所の細い枠線または文字色 ③段階の物差しがあればその 1 本。この 3 枠が予算で、余らせるほうが失敗。全部を灰色にした未完成のワイヤーフレームにしない
- **色を 1 つ消したら、余白を 1 段階広げる** — 区切りだった色を外して余白がそのままだと、のっぺりする。項目の間隔は `space-y-3` → `space-y-6`〜`space-y-10`、見出しと本文の差は `text-base`/`text-sm` → `text-lg`/`text-sm`、節の間は `mb-12` → `mb-16`〜`mb-20`
- **例外は「絵」だけ。決まりは 2 方向** — 実在の画面を模したミニ UI（天気アプリ・チャット・
 エディタ・ターミナル・ブラウザ枠）とコードブロックの色分けは、その画面らしい色のままでよい。
 あれは情報を色で符号化しているのではなく「絵」だから、明暗でも反転させない（写真と同じ）。
 - **絵の外** … 名前だけ。生の色名を書かない
 - **絵の中** … 生の色だけ。名前を混ぜない（混ざると、明暗で片方だけ動いて絵が壊れる）
 - **境目** … 外側の器に `data-ads-figure="light"` か `"dark"` を付ける。どちらかは
  **絵の地色**で決める（黒いターミナルなら `dark`、白いアプリ画面なら `light`）。
  この印 1 つで、器の輪郭・中のスクロールバーやフォーム部品・紙に刷るときの扱い・
  コメントの赤入れの色が、まとめて絵の側にそろう
- **図の文で書いた図（順序図・流れ図など）には、色を書かない** — あれは「絵」ではないので
 明暗で反転させる側。貼る一式が額縁の名前を読んで色を入れるので、**図の中の `style` や
 `classDef` に色を指定しない**（指定すると、そこだけ明暗で動かず片方で読めなくなる）。
 1 つだけ目立たせたいときは `classDef accent stroke-width:2px` のように**太さ**で示す

## 書体と絵記号

- **書体は額縁が持つ。本文に `font-family` も `font-[...]` も書かない** — 並びは OS の書体が先頭
 （`-apple-system` → ヒラギノ → Segoe UI / Yu Gothic UI → メイリオ → Noto Sans JP）。Pages の画面と同じ考え方で、Web フォントを待たない。
 図を貼る一式も同じ並び。太さは 400・500・700 を使う（`font-black` の 900 は Windows の游ゴシックに無く、太字で出る）
 等幅は `font-mono`（コード片だけ）
- **絵記号は Lucide だけ**（額縁が読み込む。`<i data-lucide="名前">`）。**絵文字を使わない**
- **同じ概念には同じ絵記号、別の概念に使用中の絵記号を当てない** — 1 ページの中で「完了」に `check` と `circle-check` を混ぜない
- 大きさは添える字と同じ（本文の字に添えるなら `w-4 h-4`）。絵記号だけを大きく置かない

## 文字サイズの決め方（役割ごとに 1 つ。迷ったらこの表を引く）

- 節の見出し（h2）= `text-xl md:text-2xl` / 図の見出し（箱の中の h3）= `text-lg`（図は「箱」ではなく「図のまとまり」として扱う。カード・補足ボックスの見出しとは別枠）
- **箱・カードの見出し = `text-base`（指定なし・16px）**、**箱・カードの中の本文 = `text-sm`**。この 2 つを混ぜない
- **箱にもカードにも入っていない本文 = `text-base`**（地の文と同じ）。誤解の答えやまとめの説明もこれ
- 図の中の登場人物の名前 = `text-sm`（主役だけ `text-base`）、説明・矢印ラベル = `text-xs`
- 注記・出典・キャプション = `text-xs`
- **下位の要素を上位より大きくしない。** 箱の中の箇条書きが箱の見出しより大きい、図の中身が図の題と同寸、はどちらも階層の逆転
- **目盛り外の値（`text-[10px]` など）を書かない。** 例外は実在の画面を模したミニ UI の中だけ（実物を縮小した絵なので、対応する要素が一律に縮むのは正しい）
- **図を縮めない。** 図の文で書いた図は、名前が `text-sm`・日付や帯の中が `text-xs` で出るようそろえてある。器に合わせて全体を縮めると、その字だけが目盛りから外れる（狭い画面では 5px まで落ちる）。幅が足りないときは縮めずに横へ送るので、**図を囲む要素で幅を絞らない**
- **図の中も「名詞は本文の字、動詞は添え字」。** 節点や登場人物の名前が `text-sm`、矢印に乗る札が `text-xs` の添えの色で出るよう、貼る一式がそろえている。状態遷移図は状態と札が同数だけ出るので、段差が無いと札の列が状態と対等に読まれる。順序図のやりとりだけは**その図の主役**なので `text-sm` のまま（貼る一式がそう扱う。こちらで書き換えない）

## 線と箱の使い方

- **区切りの横線は、本当に必要なときだけ** — 既定は余白で分ける。線を引く前に「余白を 1 段広げて足りないか」を必ず試す。項目の間は `space-y-12` の余白があれば、線が無くても十分に分かれる
- **線を引いてよいのは 4 つだけ** — ①本文とフッターの境目 ②補足ボックスの左 1px（「ここがポイント」の印）。③**図の中の経路**（矢印・往復路の線）。これは区切りではなく「関係を示す線」なので、図の中に限って引いてよい。ただし `border-ads-line` 程度の細さに留める。④**表（`<table>`）の格子**（`border border-ads-border`）。表だけは余白で列をそろえられないので、行数によらず縦横とも引き、外枠も付ける——縦線が無いと、狭い列（記号や数字）と広い列（文章）の境目が読めない。**ページ上端の色の帯は引かない**——読み始める前に目に入る唯一の色が、本文のどの意味とも結びつかない
- **箱の中に同じ色の箱を入れない** — 外側に面（`bg-ads-surface`）を敷いたら、その中の要素は面も枠も持たせない。中を分けるのは余白。同じ色・同じ角丸の箱が二重になると、輪郭が増えるだけで階層は生まれない
- **箱は「ここまでが 1 つの図」を示すときだけ** — 本文の流れから図を切り出す用途に限る。並列の項目を 1 つずつ箱に入れない
- **図の文で書いた図（`<pre class="mermaid">`）には面を敷かない** — 上の「箱の中に同じ色の箱を入れない」がそのまま当たる。あの図の箱も、矢印の札の下敷きも**紙の色**なので、面の上に置くと白い四角がいくつも浮いて出る。手で組んだ図に面を敷いてよいのは、あちらが自前の輪郭を持たないから。**図の文で書いた図の切り出しは、見出しと余白で行う**
- **面＝量、線＝入れ物** — 塗りと輪郭はどちらも「囲む」役なので、1 つの箱に両方は持たせない。長さや幅が意味を持つもの（日程の帯・順序図の「呼ばれている間」）だけを面で読ませ、ただの入れ物（節点・登場人物・カード）は輪郭だけにする。**量を持たない印を、量を持つものより濃くしない**（塗りつぶした丸は面積があるぶん、輪郭 1px の部品より必ず重く見える）。図の文で書いた図はこれを貼る一式が守るので、こちらでは色も塗りも書き足さない
- **矢印は無くても順序は伝わる** — 番号と左 → 右の位置で足りる。矢印のぶん各列が狭くなり、文章が変な位置で折り返す方が損。横並びが 4 列を超えるなら、そもそも縦に積む
- **ラベルにコロンを使わない** — 「誤解:」「実際は:」「ポイント:」のようにコロンで文をつながない。ラベルが要るならチップ（`rounded bg-ads-surface-2 px-2 py-0.5 text-xs font-bold text-ads-muted`）にして、本文と別の要素として置く。チップは無彩色にする
- **同じことを 2 回言わない** — アイコンと文字ラベルが同じ意味なら、どちらか 1 つ。✗ の記号と「誤解」の文字を両方置かない
- **1 つの塊の中は、上から下へ弱くする** — まとまりの先頭が最も強く、以下だんだん弱くする。先頭を小さく薄くして 2 行目を大きくすると、目が 2 行目に飛んでから上に戻る往復が起きる。強さの軸は 大きさ → 太さ → 濃さ の順に効くので、先頭を大きく、結論を濃く、という配り方はできる。節の趣旨と視覚の主役は必ず一致させる（「よくある誤解」の節で、誤解より答えが目立つ状態にしない）
- **押せない要素を、押せる見た目にしない** — 角丸フル（`rounded-full`）＋枠線＋地色＋短い文字は「ボタン」の記号。**本文には押せるものを置かない**（PDF と先頭へ戻るは額縁が持つ）。ラベルが要るならチップ（角は `rounded` 程度、地色のみ、枠線なし）、並列の例示なら素の文字を余白で区切る
- **節の見出しには、アイコンも番号も置かない** — 見出しの文字だけにし、節の切れ目は余白の広さで示す（節と節の間は `mb-20 md:mb-24`）。7 つ並んでも疲れず、色の面も要らない。アイコンを使うのは本文中の補足ボックスだけ（塗りなしで見出しの行に置く）
- **補足は、それが補足する本文より弱くする** — 「ここがポイント」のような補足ブロックの本文は、地の文より 1 段小さく（`text-sm`）。補足が本文と同じ大きさだと、読み手には「本題が 2 つある」ように見える。同じ役割のブロックが複数あるなら、全部同じ大きさに揃える（1 つだけ大きい、が起きやすい）
- **行頭の記号は、文章の縦中央に揃える**（`items-center`）— ✗ / ✓ / アイコンを文の左に置くとき、`items-start` ＋ `mt-1` で固定すると、文が 2 行に折り返したときに記号が 1 行目に貼り付いて不揃いに見える
- **横並びを縦積みに切り替えるとき、`items-start` を残さない** — スマホで縦 1 列になったとき、各ブロックが内容の幅まで縮んで左に寄る。`items-stretch md:items-start` のように、狭い画面では幅いっぱいに伸ばす（中の `text-center` はそれで初めて効く）

## 連番の見せ方

番号つきの項目を縦に並べるとき（決定事項・まとめ・運用ルールなど）

- 数字は**大きく薄く**（`text-4xl font-black tabular-nums text-ads-border`）、固定幅（`w-14 shrink-0`）で左に置く。読ませるものではなく目印なので、薄くてよい（線の色を字に使ってよい唯一の場所）
- 数字は**要素の高さの中央**に置く（`flex items-center`）。見出しの行に合わせて上に貼り付けない
- 項目の間は `space-y-12` の余白だけ。カードの面・枠・区切り線は使わない
- 見出しは `text-lg font-bold`、本文は `text-ads-muted`（サイズ指定なし＝地の文と同じ）。この差だけで階層は足りる

## 引用・定義の見せ方

公式の定義、他所からの引用

- **ここでは箱を使ってよい。** 引用は「筆者の地の文ではなく、他所からの借り物」なので、本文の流れから切り離す境界が要る。面だけ敷き（`bg-ads-surface rounded-2xl p-8 md:p-10`）、**枠線は付けない**。「箱を減らす」の例外はここと図のまとまりだけ
- **箱ごと中央に、中の文字は左揃え**（`text-center` の親に `inline-block text-left` の引用）。文字まで中央寄せにすると、狭い画面で折り返したときに最終行が 1〜2 文字だけになって崩れる。行頭が揃っていれば、行末が不揃いでも読みやすい。2 行に分かれる箇所には `<br class="hidden md:block">` を入れて広い画面での行長を揃える（狭い画面では自然折り返しに任せる）
- **節の見出しより大きくしない。** 本文（`text-sm`）に対して `text-lg md:text-xl font-bold` まで。`text-2xl` まで上げると節の見出し（h2）と同格になり、引用ではなく見出しに見えてページの階層が壊れる
- 何の引用かは**小さな太字のラベル**で示す（`text-sm font-bold text-ads-muted`）。**面の上ではチップの背景を付けない** — 引用の箱がすでに本文から切り離しているので、ラベルにさらに面を重ねると箱の中の箱になる。白地の本文の中に置くラベル（誤解の節など）は、文と区別するために背景のあるチップにする
- **出典は箱の中に置く。** 外に出すと、どこに属する出典か分からなくなる。`text-xs text-ads-muted` で小さく添える（下線は額縁が付ける）
- 意味の通りに `<figure>` / `<blockquote>` / `<figcaption>` を使う

## 本文中のコード片（インラインコード）

`fetch()` のように文章の中に混ぜる短いコード

- **1px の枠（`border-ads-border`）＋ 等幅（`font-mono`）だけ。地は敷かない**。地を敷くと、明るい側では面から浮いた出っ張りに、暗い側では面に空いた凹みに見える（同じ書き方が明暗で逆の物になる）。枠と等幅だけなら、地の上でも面の上でも同じに見える
- **色を付けない。** 緑や青にすると、意味のある色（成功・主要）と衝突して両方が読めなくなる
