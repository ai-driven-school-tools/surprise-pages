# 自分のスキルを足す

このリポジトリには、資料を作って自分のサイト に投稿するスキルが入っている
（`explain-page`・`explain-deck`・`clean-copy`・`read-page`）。同じ形で、自分用のスキルを足せる。
たとえば「週報をいつもの形でページにする」「読書メモを清書して投稿する」のように、
繰り返す頼みごとをスキルにしておくと、毎回の説明が要らなくなる。

この文書は、その足し方の約束ごと。

## 置き場所と形

スキルは `.claude/skills/<名前>/` の 1 フォルダで、中にファイルを 2 つ置く。

```text
.claude/skills/
  _shared/references/   … 全スキルで共通の額縁・デザイン規則・投稿の手順
  explain-page/
  my-weekly-report/     … 足すスキル（名前は英小文字・数字・ハイフンだけ）
    SKILL.md            … 入口。いつ使うかと「手引き.md を読め」だけ
    手引き.md           … 手順の全部
    references/         … （任意）見本や雛形
    scripts/            … （任意）決まった処理を機械に任せるスクリプト
```

Claude Code は、このリポジトリを開いたときも、別のフォルダを開いたときも（設置でつないだプラグイン経由で）
`.claude/skills/` の下のフォルダをスキルとして読む。Cursor と Codex は、スキルごとの近道から読むので、
足したら `node <リポジトリ>/scripts/setup/skills.mjs` をもう一度打って近道を足す。
どれも、新しいチャットを開いて呼べるか確かめる。

### SKILL.md は案内役にする

既存スキルの `SKILL.md` をコピーして、`name` と `description` を書き換えれば足りる。

```markdown
---
name: my-weekly-report
description: 1 週間の作業メモを、いつもの週報の形の 1 枚のページにして自分のサイト に投稿する。「週報にして」と依頼されたときに使用する。既定は招待した人だけが見られる設定、公開はユーザーが明示したときだけ。
---

# 手順は同じフォルダの `手引き.md` にある

この SKILL.md には手順を書かない。**同じフォルダの `手引き.md` を Read で全文読み、そこに書かれた手順だけに従う。**
```

- `name` はフォルダ名と同じにする
- `description` は AI がスキルを選ぶときの手がかりになる。**どんな頼みごとで使うか**を、
  実際に打ちそうな言い方（「週報にして」など）で書く

### 手引き.md に手順の全部を書く

手順・判断の基準・禁止事項は、すべて `手引き.md` に書く。SKILL.md に分けて書くと、
片方だけ直して食い違う。

## 新しいスキルが必ずやること

**1. 共有ファイルを読む（ページを作るスキル）**

- `_shared/references/base.html` — 額縁テンプレート。配色・差し込み位置を含む。額縁の構造（`<head>`・CDN 読み込み・meta タグ）は変えない
- `_shared/references/デザイン規則.md` — 色・文字サイズ・線と箱の上位ルール

**2. 投稿は `_shared/references/投稿の手順.md` に従う**

前提確認（投稿先とログイン）から、投稿・片付け・完了報告・削除・禁止事項まで全部。
投稿は `node <リポジトリ>/bin/pages-publish.mjs` だけを使い、保管庫やデータベースへ直接書き込まない。
既定は「招待した人だけ」。公開（`--public`）はユーザーが明示したときだけ。

**3. 「スキル置き場の探し方」を手引き.md に写す**

共有ファイルを Read するスキルは、下の正本のブロックを手引き.md にそのまま写す。
手順の全部が同梱スクリプトの中にあり、AI が共有ファイルを読まないスキル（`clean-copy` のような
`scripts/run.py` 1 本で済む形）は持たなくてよい。

**4. 投稿しないスキルは、投稿にかかる分を持たない**

出ているページを**読む**だけのスキル（`read-page`）がこれで、額縁もデザイン規則も投稿の手順も読まない。
ただし**直す起点になるスキル**は、本文を戻したあとの投稿までひと続きで頼まれることがあるので、
投稿の手順への案内は入れておく。

**5. デザインを変えたいときは、既定からの逸脱を手引き.md に明記する**

`デザイン規則.md` は全スキルの**既定**であって、全スキルが一言一句同じデザインになる、という意味ではない。
違う見せ方をしたいスキルは、黙って無視するのではなく、**「外すもの」と「読み替えるもの」を列挙する**。
書いていない項目は既定に従う、と読めるようにしておく。

**6. 既存スキルとの分かれ目を description に書く**

どんな依頼が自分に落ちて、どんな依頼が他のスキルに行くべきかを書く。既存スキルの
description と食い違うと、依頼のたびに違うスキルが立ち上がる。迷いやすい境目には
「迷ったらどちらに倒すか」まで書く（例: clean-copy は「迷ったら内容を変えない側に倒す」）。

## 守ること

- **秘密を書かない。** 鍵・パスワード・自分のサイトの管理用の接続情報を、スキルのファイルに書かない。
  投稿の鍵は `node <リポジトリ>/bin/pages-publish.mjs login` の控えだけを使う
- **既存スキルと共有ファイルを直すときは慎重に。** `_shared/references/` は全スキルが読むので、
  直すと全スキルの振る舞いが変わる。自分のスキルだけ変えたいなら、自分のフォルダの中で済ませる
- **配布物の更新と混ぜない。** 配布元の新しい版を取り込むとき、既存スキルを直していると食い違いが出る。
  自分の工夫は、できるだけ自分で足したスキルのフォルダに置く

## 「スキル置き場の探し方」ブロックの正本

直すときは、まずここを直し、それからこのブロックを持つ全スキルの**手引き.md**へ同じものを配る
（SKILL.md ではない。SKILL.md は案内役で、このブロックを持たない）。

~~~markdown
### スキル置き場の探し方

このスキルは、このリポジトリ（Pages の配布版）の `.claude/skills/` に入っている。
以下では、

- `<リポジトリ>` … このリポジトリの一番上のフォルダ（`bin/pages-publish.mjs` と `deployment.json` があるところ）
- `<スキル置き場>` … `<リポジトリ>/.claude/skills`（各スキルのフォルダと共通の `_shared/` が並んでいるところ）

と書く。スキルは別の仕事のフォルダからも呼ばれる（Claude Code のプラグイン、Cursor・Codex の近道）。
`<リポジトリ>` は、読んだ SKILL.md の**実体**から 3 つ上のフォルダ（`<リポジトリ>/.claude/skills/<スキル名>/SKILL.md`）。
近道越しに見えていても、近道の先で数える。最初に 1 回だけ、次で求めて確かめる。

```bash
python3 -c 'import pathlib,sys; p=pathlib.Path(sys.argv[1]).resolve().parents[3]; print(p if (p/"bin/pages-publish.mjs").is_file() and (p/".claude/skills/_shared/references/base.html").is_file() else "")' <読んだ SKILL.md のパス>
```

フォルダが 1 行出れば、それが `<リポジトリ>`。以降ずっとこれを使う。
コマンドは**いま開いているフォルダのまま**、`<リポジトリ>` を前に付けて打つ（`node <リポジトリ>/bin/pages-publish.mjs …` の形）。
作業ファイル（`page-out/` など）も、いま開いているフォルダに作る。
何も出なければ、配布物が欠けている。推測で探し回らず、そう伝えて止まる。
~~~
