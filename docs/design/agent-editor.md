# リンクから安全に更新する編集基盤

2026-09-18。保存済みHTMLを正本として、人間とエージェントが同じ変更操作・履歴を利用する。

## 利用する流れ

一度だけ共通プラグインと接続を導入し、既存の会社ログインを済ませる。以降はCodex／Claude Codeに資料のリンクと修正の依頼を渡す。

概要 → 必要な枚・要素 → 変更案 → 描画検査と見本確認 → 保存 → 変更点と確認リンク。
通常の修正に人間の承認画面を挟まない。原稿の再取り込みと資料全体の復元は明示依頼時に限定する。

## サービス側

- `POST /api/pages/agent` は既存の名乗りと資料の権限を利用する。`GET` は本文を含まない対応版の確認。
- 入力の正本は `src/lib/page-agent/model.ts`。`action` は read / prepare / preview / verify / apply / history / revert / restore / reimport。本文の形式による機能差は返却する対応操作で判断する。
- read は概要・対象の詳細・必要箇所の原文・コメント・デザイン設定を分ける。文字組みや配置は、画像を取らず実寸と計算済みの書体・余白を取得できる。続きは同じ版に固定する。本文と版は同じ保存済み記録から採り、読取だけでは永続目印を追加しない。
- prepare は取得版に本当に存在した変更前の値を検証する。一依頼は最大256操作・送信1MB。上限超過で勝手に分割保存しない。
- 変更案には操作だけを保存し、3日で失効する。履歴と受領記録は残す。依頼番号の再利用は、下書き削除後も永続する受領記録で拒否する。
- 文字、装飾、表セル、グラフの値、ノート、設定項目を個別に照合する。エージェントの同じ文字枠への変更は競合として返し、自己申告の利用製品名で方針を変えない。
- 検査した本文と反映本文を照合する。別の枚への変更だけなら、対象枚・共通設定・枚順が変わっていないことを確認して検査を再利用する。
- 受領記録には実際に保存した版とその親を結び付ける。再送応答は元操作の保存版と現在の最新版を区別する。
- 編集画面は未受信の操作を取得する。途中に全体置換や読めない記録があれば、飛ばさず全体取得へ戻す。
- 元原稿の再取り込みは選んだ既存の目印だけを変更案にする。対応不明は未適用として残す。旧投稿はスライド更新時の土台版が必須。既存スライドへの旧素材上書き・一括削除は停止する。

## 接続・検査・配布

- MCPの入口は `bin/pages-agent.mjs`。既存投稿コマンドの名乗りと通信を再利用する。画像・動画も同じ編集用の非公開アップロードを通す。
- 操作の入力形式は共通スキーマから生成する。道具の説明文だけで形式を推測させない。再生成は `node scripts/build/agent-tools.mjs`。
- 描画検査は1280×720原寸・2倍密度で画像の画素数も確かめる。切り抜きの拡大とsrcsetの密度補正を含め、変更対象の枚にある不足・欠損を停止理由にする。既存の不足も除外しない。
- 描画検査は隔離したブラウザで行う。資料の素材と自前の配布物以外へ認証情報を送らず、外向きHTTP・WebSocket・Service Workerを遮断する。
- Playwrightのブラウザが無ければインストール済みのChromeを利用する。どちらも無い場合は検査を未完了として止める。動画の静止画作成にはffmpegを使う。
- 正規投稿コマンドも画像付きスライドを送信前に描画検査する。検査道具が無い単体CLIでは停止し、画像無しの記事・スライドは従来どおり扱う。配布物には原稿用の検査入口も含める。
- 共有プラグインの配布物はサービス側から生成する。生成物を直接修正しない。

```sh
node scripts/build/agent-tools.mjs --out /absolute/path/to/surprise-plugins/plugins/surprise-pages/scripts/agent-runtime
```


## 確認・取り消し

履歴と資料メニューから「今回の変更」を開く。変更した枚だけを同じ位置・倍率で前後比較し、本文・機械検査・AI所見・未対応を分ける。過去の見本から追加指示を作るときは、現在版ではなく表示した版を記録する。削除された枚へ別の枚を代わりに割り当てない。

取り消しは逆操作を新しい依頼として検査・保存する。後続の他者編集は残し、重なれば比較に戻す。構造に依存する取り消しは一部だけを選べない。全体復元は過去版を新しい版として保存し、当時の素材は変更不能な参照へ保護する。凍結されていない古い素材、解像度別画像や未対応の背景画像を含む復元は停止し、現在の素材で代用しない。

## 展開順と確認

1. 追加の保存先定義を適用し、サーバーを更新する。既存HTMLの一括変換はしない。
2. 対応版を確認してから共有プラグインを更新する。共通手順・配布目録の版を揃える。
3. 限定した社内資料で両製品の操作を確認してから利用範囲を広げる。停止時は `PAGES_AGENT_EDITING=off` で入口を止め、履歴は維持する。

本番の保存先変更・配布は、ローカル実装と試験とは別に実施状況を記録する。

```sh
node tests/checks/check-page-agent.mjs
node tests/checks/browser/page-agent-workflow.mjs
DECK_BROWSER=webkit PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node tests/checks/browser/page-agent-workflow.mjs
PAGE_AGENT_QA_ORIGIN=http://127.0.0.1:PORT node tests/checks/browser/page-agent-real-clients.mjs
pnpm verify
```

実際のエージェント試験は試験用のローカル資料だけに接続する。終了コードだけで合格にせず、保存成功の道具呼出しと保存された内容を確認する。履歴の閲覧、公開範囲、機械検査が未完了の状態を成功として報告しない。

効率は依頼一式の所要時間、モデルへ返した文字量、画像枚数、再試行、人の介入を記録する。実クライアントの使用量は会話の共通指示とキャッシュも含むため、HTMLサイズとの差をそのままトークン削減率と呼ばない。


## この実装での検証記録

- サーバー側の検査は、文章の構造変更、別の値の同時更新、保存中の取り消し、検査後の共通描画条件の変化、古い素材の欠損を含む。
- 新しい一連の操作はChrome系・Safari系で確認。既存の制作操作18場面も両方で確認した。
- 実際のCodexで「リンク＋見出し変更」、Claude Codeで「リンク＋文章を維持した読みやすさの改善」を行い、保存成功と履歴を確認した。初期試験で見つかった形式の推測による再試行を、共通の入力契約と具体的なエラーへ置き換えた。
- 日本語の変換開始・取消・確定をブラウザの変換イベントで検証し、文字と字体の保持を確認。実OSの日本語入力による検証とは区別する。
- 一連の試験でモデルへ渡す本文情報は約32KB、比較対象のHTML一式は約641KB。これは情報量の実測であり、実クライアント全体のトークン削減率ではない。
- 本番の保存先への適用、共有プラグインの配布、利用者全員への接続登録は、このローカル実装・試験では実施していない。
