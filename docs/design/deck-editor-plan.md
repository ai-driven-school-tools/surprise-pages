# 白紙から作って仕上げるスライド編集

2026-09-19。全見本を見てテーマを選び、空の資料から作成する。

## 体験と画面

「テーマと任意の資料名 → 作成 → 編集画面で最初の一枚を追加 → 発表」が基本の流れ。パソコン中心。AI生成・複雑な図の専用編集は対象外。

一覧から `/decks/create` を開く。左に12テーマの色見本、右にブラウザで追加・編集できる全64種類の見本を並べる。分類・検索・拡大確認を使えるが、ここで見た見本を資料へ入れない。16:9固定、名前の空欄は「無題の資料」。「このテーマで作成」まで保存せず、決定するとテーマと名前を持つ0枚の資料を開く。決定操作は一覧のスクロールに埋もれない。

作成画面は上下の操作を固定し、中央だけをスクロールする。マイテーマは名前を読める選択欄、標準12テーマは通常幅で2列、狭い幅で3〜4列に並べる。分類は検索と同じ行の選択欄に置き、横スクロールをなくす。見本の遅延描画は中央の表示範囲に従い、テーマを変えても閲覧位置を保つ。拡大面だけは画面全体を表示判定に使う。

編集画面の空状態はテーマ名と「最初のスライドを追加」を示す。最後の一枚を削除したときも同じ状態へ戻る。発表・要素の挿入・ノート・この枚だけの配色は、対象の枚があるときだけ出す。資料全体の配色は0枚でも変更できる。

ブラウザで主要内容を編集できる見本の許可表は `src/lib/deck/design/browser-templates.ts`。基本8種類と確認済みの見本56例を、一覧・追加・サーバーの検査で共用する。元の94例は削除しない。図表の描画方式や分類だけで編集可と推測せず、新しい見本は確認後に許可する。

画像欄を持つ見本は、内容に沿った画面例とイラストを初期表示する。既存の画面例・手順イラストの生成器と `scripts/generate/deck-catalog/sample-scenes.mjs` から、見本の組み立て時に小さなSVGを作る。外部画像や別資料の素材を参照せず、生成した画像ファイルもリポジトリへ追加しない。画像欄の内側に置くため、一覧・拡大・追加後・再読み込みで同じ絵を保つ。追加後は画像欄を選んで、通常の非公開アップロードで自分の画像に差し替えられる。文字だけの見本や白紙には画像を足さない。

### 見本の軽量表示

テーマ一覧と編集途中の追加は同じ見本表示を使う。`src/widget/deck/edit/template-preview.ts` が実行する描画画面を1つだけ持ち、既存の描画・更新・解放の受け口を使う。描画と書体の準備後に本文・適用済みスタイル・読み込み済みの書体を固定した写しにし、一覧では実行コードのない静止表示だけを使う。見本の写しを資料の正本や保存内容へ混ぜない。

表示中と前後1行を優先して順次描画する。最近使った写しは見本・テーマ設定ごとに最大24件保持。描画部品と見本の版は読み込んだモジュールに固定し、更新した版では新しいキャッシュを作る。画面外の表示は解放し、同じ見本の再表示と拡大ではキャッシュを使う。テーマ連打では古い待機を取消し、最後の選択だけ反映する。初期化と描画は8秒で打ち切り、共有画面を作り直して残りを続行する。失敗カードは押して再試行できる。

- 上部52px: 資料名、取り消し、挿入、デザイン、保存状態、発表、完了。
- 左200px: 番号列と縮小画像の一覧。ヘッダーは固定し、一覧だけをスクロール。追加は文字付きのボタン、要素切替は絵記号、並べ替え・複製・削除はメニューとキーボードから使う。
- 中央: 一枚全体を表示。倍率・左右のパネルは本文に保存しない。
- 右264px: 選択に応じた文字・画像・動画・図形・表・基本グラフの調整。未選択時は「レイアウト＋現在値」「背景＋色見本」のみ。詳細な配置は折り畳み、説明は下部の操作ガイドへ集約。デザインも同じ欄で切り替える。
- 下部36px: 現在の枚、ノート、倍率。狭い画面では左右を一つずつ開く。
- 共通の部品と動作は `src/widget/deck/workspace/workspace.ts`、見た目は `src/widget/deck/workspace/styles.ts`、絵記号は `src/widget/deck/ui.ts`（16px・線幅1.7px・32pxの操作領域）。保存・通信は `src/widget/deck/edit/session.ts`、直接操作は `src/widget/deck/canvas.ts`。

新規資料は社内限定で0枚から始める。追加時は「現在のN枚目の後に追加」を表示し、その位置に追加する。新規作成口は保存先・公開範囲・任意HTMLを受け付けず、本人と一回の作成依頼から保存先を決める。二重送信で資料を増やさない。

## マイテーマ

本人のアカウントへ、資料全体の配色・書体・ロゴ画像と配置を保存する。本文・画像・枚別の調整は保存しない。既存4書体を編集画面で選べ、0枚でもロゴ設定を持つ。設定がない旧資料には最初のロゴ操作で標準設定を追加する。

編集の保存完了後、サーバーは編集権限と指定版を確認して正本から設定を抽出する。テーマ台帳と変更不能な版を持ち、更新には期待する版が必要。同じ依頼番号は受領済みの結果を返す。ロゴはテーマ用の非公開保管先へコピーし、資料に適用するときにはさらにその資料へコピーする。コピーの再送では内容と種類を照合し、違う画像を成功扱いしない。元資料・テーマの更新や削除は既存資料へ反映しない。

テーマ選択は「マイテーマ」「標準テーマ」に分け、編集からも保存・明示的な更新・適用ができる。名前変更と削除は管理画面で行う。ロゴなしの適用は現在のロゴも外し、その旨を事前表示する。枚別設定は保持し、適用は既存の操作履歴で一度に取り消せる。ロゴ画像の追加・削除は不完全な途中状態を作らず、設定一式の操作として扱う。

新規作成にはマイテーマのIDと版を指定できる。受付済みの依頼は3日間同じ版を使う。作成済み資料の確認を先に行うため、元テーマを削除しても応答不明の作成を再試行できる。未受付の旧版は再選択を案内する。履歴の版は少なくとも控えの有効期間を超えて保持し、v1では自動で物理削除しない。

見本は既存の描画を使い、ロゴを一度取り寄せて静止表示間で共用する。描画用の画像URLは文書上の一時的な受け口にだけ渡し、保存HTMLに混ぜない。表示と24件のキャッシュから不要になった画像は解放する。ロゴを置ける場所は構図側の安全域に従い、非表示になる構図は拡大面で案内する。

公開順はテーマ用のデータベース追加、次にアプリの更新。本人確認はブラウザの会社ログインを使い、投稿鍵やローカルの仮の人には受付を開かない。会社共有、独自フォント、既存資料の自動更新は対象外。

## 正本と操作

- 本文の正本はHTMLだけ。独立した本文JSONや別描画器を作らない。
- `src/lib/deck/edit/model.ts` の操作へ、断片の挿入・削除・置換、並べ替え、属性、資料設定を追加。`src/lib/deck/edit/source.ts` が原文の位置から差分だけを反映する。
- 変更対象の以前の内容を照合し、違う場合は競合にする。正本・逆操作・受領記録は既存の保存処理で一緒に記録する。
- 本文・行・列・セル・系列・点の目印は維持する。複製は新しい目印と参照の対応表を作る。コメントは複製しない。
- 共通の型は `src/lib/deck/authoring.ts`。新規資料は既存の `src/templates/deck.html` と `src/templates/deck-design.html` を埋め込む。配布の許可表も同時に生成する。
- グラフは既存のECharts SVG描画。基本グラフの目印を持つものだけ専用編集を許す。空欄とゼロを区別し、重複ラベルでも位置を保持する。複雑な既存図のデータを基本グラフへ変換しない。
- 画像・動画は既存の非公開素材経路を使う。差し替え対象は送信単位に固定し、選択のキャンセルで破棄する。

## 発表でスキップ

左一覧の操作メニューから選択した複数枚をスキップ・解除できる。スキップは枚の `data-deck-skip="true"` に保存し、本文・通常閲覧・印刷は残す。発表の前後・先頭末尾・リンク・一覧ではスキップした枚へ移動しない。全枚がスキップなら開始を止めて解除方法を示す。

既存の標準ナビゲーションは、最初のスキップ変更時に `navigation` 設定操作で更新する。更新元は `src/templates/deck-navigation-legacy.json` に控えた既知の完全一致だけ、更新先は生成済みの標準部品だけを許す。更新も逆操作を持ち、スキップと一緒に元に戻せる。独自の実行コードは書き換えず理由を伝える。親子関係を将来追加してもスキップは枚ごとの指定とし、親から自動継承しない。

## 表示と読み込み

表示中の資料を保ち、変更対象だけを更新する。原本・画面へ適用した内容・描画完了した内容・保存の受領を別々に持つ。自分の保存受領で表示が同じなら描き直さず、入力中に届いた他人の変更は入力終了後に必ず反映する。

- 更新判断は `src/widget/deck/render.ts` に集約。原本同士の比較から、変更した文章・配置・設定・構成だけを既存の描画へ反映する。変更していない図表や動画の実体は保持する。表示側の木を保存しない。
- `src/lib/deck/render-contract.ts` が、構成の再収集、対象を指定した描画、完了通知、取り外す対象の解放をつなぐ。構成の変更後も発表の順序・枚数・ノート・補足・深いリンクを同じ実行部で更新する。
- 原本の解析は直近2つだけ再利用する。解析した木を書き換えず、原本の文字列へ差分だけを当てる。画面の選択や保存状態だけの変更では原本を再解析しない。
- 左一覧の行は枚の目印で再利用。縮小表示は枚の内容・実効配色・ロゴ・描画環境の世代で更新を判定し、見える範囲と上下2枚を優先して最大2件ずつ準備する。準備中は前の縮小表示を残す。失敗は2回まで再試行し、その後は通信復帰を待つ。
- 配色は同じ文書へ反映する。新しい書体は準備後に反映し、古い準備結果で新しい指定を戻さない。設定欄の入力位置と開いた詳細は維持する。
- 部分更新できない外側の構成や独自HTMLは、別の非表示領域で準備してから入れ替える。前の表示は成功まで保持し、失敗した部分更新の再試行もこの経路を使う。現在の枚・倍率・一覧の操作位置を引き継ぐ。
- 既存資料は、既知の標準部品と完全に一致するものだけを編集用の表示で更新する。照合表は `src/templates/deck-preview-compat.json`、配布用の部品は共通雛形から生成する。独自の実行処理と保管済みHTMLは書き換えない。

## 入力・保存・復帰

新規作成の依頼は、テーマ・名前・最初の一枚なしの指定と一意な依頼番号を送信前に同じタブへ控える。旧来の呼び出しは表紙を既定とし、以前の最初の見本を持つ未確認の依頼も指定を書き換えずに再送する。アカウント別、3日で失効。通信結果が不明な間は指定を固定し、再読み込み後も同じ依頼を再送する。作成済みなら同じ資料へ戻る。移動先の編集画面を開けた時点で控えを消す。サーバーは保存先と社内限定を決め、任意HTMLや公開指定を受けない。資料名とスライド内の見出しは別に保つ。

日本語入力の表示反映と正本の受領更新を分離する。入力中でも保存済みの正本は進め、遠隔表示の反映だけを入力確定まで待つ。未送信の操作はその場で取り消し、送信済みなら同じ送信を受領してから逆操作を適用する。

通信断では3日間の操作下書きを保持。衝突した変更は、自分の内容をコピー可能な状態で最新版と比較する。対象の消失を別の場所への自動適用で補わない。送信中は進捗を出し、保存済みと表示しない。

発表者ノートと読み手への補足は別入力。ノートの保存先は入力欄を開いた枚へ固定する。ノートは公開・印刷へ出さず、読み手向け補足は既存の段階表示の設定を使い、閲覧・印刷に残す。

## 互換性

既存の本文編集、デザイン・焦点・ロゴ設定の保存契約を維持する。エージェントの更新と変更案の保存先は [エージェント編集](agent-editor.md) にまとめる。原稿の再取り込みも最新版と比較して採用する変更を選び、現在の修正を一括上書きしない。構図を変えられない独自HTMLは表示を保ち、安全に扱える操作だけを提供する。


## 素材の取り込みと軽量化

- 既存の画像・画像欄の上へのドロップは、その画像の差し替えにする。位置・寸法・切り抜き・目印を保ち、1回の取り消しで元の画像へ戻せる。余白へのドロップは追加にする。ドロップ前に対象の輪郭と短い案内を出す。ロック中の画像は差し替えず、複数ファイルの差し替えは受け付けない。
- ファイル・外部ページからのドラッグ、画像の貼り付け、挿入画面のリンク入力を同じ待ち行列へ送る。送信は最大2件、各要求は2MB以下。画像10MB、動画100MB。追加先と差し替え対象は受付時に固定する。進行状況は下部の固定入口にまとめ、スライドへ通知を重ねない。利用者が開いたときだけ、右の調整欄を素材の状況へ切り替える。狭い画面では明示的に開いた素材欄へ表示を切り替え、閉じると編集へ戻す。失敗はファイル名・原因・次の操作の順に示し、形式・破損・容量は選び直し、通信は再送、保存は既存の復旧操作へ導く。通信上の理由を機械用の分類で渡し、文言を条件判定に使わない。赤は下部の小さな確認の印だけ。完了分は折り畳む。
- 画像はサーバーで向きを補正し、長辺2560px以内へ縮小する。透明部分を維持し、小さくならない画像と動く画像は原本を保つ。原本と変換結果は非公開・変更不能な素材として保存する。
- 動画は配置の保存後、処理台帳へ登録し Workflow と Vercel Sandbox で変換する。同時処理は利用者ごとに2本、処理時間は15分、各手順の自動再試行は2回。実行番号で別の処理の横取りを防ぎ、変換器の重複起動も防ぐ。最大1080p・30fps、音声を残す。小さい動画は引き伸ばさず、透過・HDRは原本を使う。処理状況は画面を開き直しても取り戻せる。
- 完了時は現在の編集権限・対象の目印・元の参照を照合する。配置や文章を上書きせず、動画の参照だけを既存の保存経路で置き換える。中止された処理や削除・差し替えされた対象へ反映しない。変換前後の容量と時間は台帳に残す。
- 外部取り込みはHTTPSの画像・動画の実体だけ。名前解決した接続先を固定し、転送ごとに公開アドレス・形式・容量・時間を検査する。ブラウザのログイン情報を引き継がず、取得できない素材はファイルでの追加を案内する。
- YouTubeは動画IDと説明・代替リンクだけをHTMLに保存する。再生操作まで外へ通信せず、再生禁止・削除・接続失敗時は理由と元の動画へのリンクを示す。生成した再生枠はコメント位置と書き出しから除外し、印刷は代替リンクを残す。

## 親子の一覧

- 親・子・孫の3段まで。本文HTMLの各枚は兄弟のまま、親の永続IDと発表順を一つの操作で保存する。通常の発表では全枚を親から子の順に表示し、明示的なスキップだけを飛ばす。
- 一覧内の移動はキャンバスと同じポインター操作へまとめる。上下へのドラッグは前後移動、横へ24px以上ずらすと子へ移動する。タッチでは番号の列をつかんで移動し、縮小画像の上では一覧をスクロールできる。折り畳み、子孫数、挿入先の案内、一覧の端での自動スクロールを備える。メニューでも前後・子にする・親の階層へ戻すを操作できる。左右キーで折り畳みと展開ができる。
- 親の移動・複製は子孫も含める。親の削除は子を繰り上げるか、まとめて削除するかを選べる。複製・削除・取り消しの途中形ではなく、保存する一括変更の最終形で親子関係を検査する。

## 導入・運用

最初に追加の処理台帳の移行を適用し、次にアプリを更新する。本番での台帳更新と公開は開発時の検証とは分ける。Vercelでは Workflow の実行環境と Sandbox を利用できるプロジェクトが必要。Sandboxへの認証は既定のOIDCを使う。ローカルから実際のSandboxを使う場合は公式SDKの認証設定が必要だが、検査は専用DB・ローカル変換器を使い本番へ接続しない。

新規変換を止めても、保存済みの原本と軽量化済み素材は通常の非公開素材経路で読める。一時送信データは既存の日次処理で片付け、完成品・履歴・原本を消さない。既存資料を一括変換しない。

検証: `check-deck-outline.mjs`、`check-deck-media.mjs`、`check-deck-edit-upload-ui.mjs`、`tests/checks/browser/deck-media-outline.mjs`。変換器の実検証にはFFmpegとffprobeを使う。Chrome系とSafari系で親子操作・送信・失敗表示・外部動画の遅延読み込みを確認する。
