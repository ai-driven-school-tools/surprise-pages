# 自分のサイト のページを読む

自分のサイトのページのリンク（`https://自分のサイト/internal/…` か `/public/…`）を渡されたら、**中身は読める**。
読むのに要るのは鍵 1 つで、それはこのリポジトリで 1 回ログインしたときの控え
（`node <リポジトリ>/bin/pages-publish.mjs login`）。**ページごとの用意も、その場のログインも要らない。**

**WebFetch・curl・ブラウザで開こうとしない。** 招待した人だけのページ（`/internal/…`）はログインで
守られているので、素で取りに行くとログインの画面か、中身の入っていない器が返る。
そこに書いてあることを推測で埋めると、**読んでいないものを読んだことにしてしまう**。
取れるのは、鍵を添えて自分のサイトの口を叩いたときだけ。それをやるのが下の 1 本。

読み先は、投稿コマンドに設定した自分のサイトだけ。ほかのサイトのリンクを渡されても、そこへは鍵を送らない
（道具が断る）。

## 打つのは 1 本だけ

`run.py` は**この手引きと同じフォルダの `scripts/` の中**にある（`<リポジトリ>/.claude/skills/read-page/scripts/run.py`）。**改めて探さない**。

```bash
python3 <この手引きのフォルダ>/scripts/run.py read https://自分のサイト/internal/guides/api-basics
```

パスは**そのまま書く**。引用符で囲んだり `RUN=…` に入れて `"$RUN"` と書いたりすると、
許可されているコマンドの型（`python3 *read-page/scripts/run.py *`）に当たらず、毎回確認を挟むことがある。
Windows で `python3` が見つからないときは `python` か `py` で同じものを呼ぶ。
`<リポジトリ>` はこの手引きの**実体**から 3 つ上のフォルダ（近道越しに見えていても近道の先で数える）、`<スキル置き場>` は `<リポジトリ>/.claude/skills`。
コマンドはいま開いているフォルダのまま打つ。

渡すのは**ユーザーが貼ったものをそのまま**でよい。`/internal/…`（招待した人だけ）も `/public/…`（公開）も、
素のスラッグ（`guides/api-basics`）も、チャットツールの `<URL|見出し>` 形式も、
マークダウンの `[見出し](URL)` も、そのまま読み取る。

| やること | 打つもの |
| :--- | :--- |
| 読む | `read <URL>` |
| 長いページを少しずつ読む | `read <URL> --save 読んだもの.txt`（あとで Read / Grep する） |
| 過去の版を読む | `read <URL> --version 02be568`（履歴の画面に出ている 7 桁） |
| コメントを見て直す | `revise <URL>`（既定の置き場は `page-out/`。HTML 全文は出さない） |
| 投稿用の HTML だけ戻す | `read <URL> --out page-out`（直す起点には使わない。`index.html` を全文読まない） |
| コメントを見る | `comments <URL>`（既定は未解決だけ。`--all` ですべて） |
| コメントを書く | `comment <URL> --body "…" [--priority must\|better\|want]` |
| 解決にする／戻す | `resolve <コメントの番号>` ／ `reopen <コメントの番号>` |

終了コードは **0 = 済んだ / 1 = 止まった / 2 = そもそも走れない**。
一覧は `run.py --help`、道具そのものの点検は `run.py --self-test`（通信しない）。

## 鍵が無いと言われたら

止まったときの文に、やることが出る。**その文をそのままユーザーに見せる。** 言い換えて短くしない。

やることは、ユーザーが次を打つことだけ。

```bash
node <リポジトリ>/bin/pages-publish.mjs login
```

ブラウザが開くので、サイトを設置したときの本人の Google アカウントで許可する。一度済ませれば、
そのパソコンでは以後何も要らない。投稿先がまだ設定されていないと言われたら、先に
`node <リポジトリ>/scripts/setup/personal.mjs configure` で自分のサイトの URL を設定してもらう。

- **エージェントがブラウザを開かない。** 開くのはユーザー本人
- **鍵の中身を画面に出さない・チャットに貼らせない**
- クラウドの作業環境から読むときは、先に `login --remote` で名乗りを用意する（README の第 4-4 章）

## 読んだあとの振る舞い

- **書いてあることだけを使う。** ページに無いことを足さない。数字・固有名詞・日付は**そのまま**写す
- **要約を頼まれていないのに要約しない。** 「読んで」と言われたら、まず何が書いてあるかを答える
- 引用や参照をするときは、**表題と URL**（と、必要なら版）を添える。どこから来た話かが後から追える
- 図（`mermaid`）は文のまま出てくる。図の中身も本文として扱ってよい
- 画像は `[画像: …]` としてだけ出る（絵そのものは取り寄せない）。絵の中身が要るなら、
  ユーザーにその画像を見せてもらう。**見えていないものを説明しない**

## 既存のページを直すとき

**白紙から書き直さない。HTML 全文も読まない。** 打つのは `revise` の 1 本。

```bash
python3 <この手引きのフォルダ>/scripts/run.py revise <URL>
```

置き場の既定は `page-out/`。すでに `index.html` / `原本.md` / `本文.md` があるときは断られる
（前回の本文と混ざるため）。片付けてから打ち直す。`--out` で場所を変えてもよい。

スクリプトが種類を見分ける。画面に出るのは種類・表題・URL・版・目次・未解決コメントと、次にすること 1 行。

**清書**（末尾に出所の切手 `data-source-note` がある）

- 読むのも直すのも `page-out/原本.md`
- 完成見本の HTML は読まない・触らない
- 差し替えたら、清書のスキルで同じスラッグへ出し直す。`--public` は元のまま
- 見た目だけの指摘（「見出しが小さい」など）は HTML を触らず、報告に残す
- 原本が取れないときは止まる。HTML から文章を復元して直さない

**図解**（切手が無い）

- **文脈**は `page-out/本文.md`（HTML を文章に開いたもの。ここを直して投稿しない）
- **直す**のはコメントが指している付近の HTML（`page-out/snippets/<番号>.html`）
- `page-out/index.html` は投稿用。**最初から読まない。** 断片を手がかりに、そこだけ差し替える
- 本文.md が長いと案内が出る。必要な見出しの付近を Grep する
- 投稿は図解のスキルへ。スラッグと `--public` は元のまま

禁止:

- 完成見本の HTML を最初から読む
- 清書なのに HTML を直す
- 図解の本文.md（読む用の訳）を直して投稿する
- コメントに無い改稿、白紙の作り直し

スライド（deck）は対象外。原本は git の HTML なので、リポジトリの原本を直す。

画像や動画は保管庫に置いたままなので、手元で開くと絵は出ない。
**割れて見えても直さない**——そのまま投稿し直せば元どおり出る。
**ゴミ箱を掘り返さない。** 正本は保管庫にあり、そちらのほうが新しい

### 配信元が後から足すと楽になるもの

この道具は、返ってきたら使う口をすでに持っている。無ければ今の探し方に落とす。
欄の形は同じフォルダの `references/配信元の契約.md`。

- 清書の投稿時に、マークダウン原本を保管する（`GET /api/pages/source` の `markdown` または `sourceMarkdown`）。公開ページでは手元の住所を外に出さない
- コメント作成時に、人が選んだ範囲の HTML を短く残す（`quoteHtml`）。断片はそれを優先する

## コメントを扱うとき

- **勝手に書かない・勝手に解決にしない。** ユーザーが頼んだときだけ。書き込みは全部
  ユーザー本人の名前で残る（鍵はその人のもの）
- 書く前に、**何をどのページに書くか**を 1 行で見せて確認を取る
- `--priority` は `must`（直さないと困る）/ `better`（直すとよい）/ `want`（好み）。
  迷ったら `want` に倒す
- 解決にするのは、**直したことを自分で確かめられたときだけ**

## 止まったとき

`止まりました:` の後ろと、その下の「次にすること」を**そのままユーザーに見せる**。
自分で言い換えない。よく出るのは 3 つ。

| 出るもの | 何が起きたか | やること |
| :--- | :--- | :--- |
| 鍵がありません／鍵が通りませんでした | このパソコンでまだログインしていない・切れている | 上の「鍵が無いと言われたら」をそのまま案内する |
| そのページはありません | スラッグ違い・`/internal/` と `/public/` の取り違え・消されたページ | URL をユーザーに確かめる。**当てずっぽうで別のスラッグを試さない** |
| つながりませんでした | 自分のサイトが止まっている・通信が塞がれている | 少し置いて 1 回だけ試し、それでも駄目なら自分のサイトがブラウザで開けるか本人に確かめてもらう |

## 守ること

- **読めなかったものを読んだことにしない。** 止まったらそう言う。中身を推測で埋めない
- **鍵の中身を出さない**（鍵を表示するコマンドを打たない。控えのファイルも開かない）
- **消さない・公開しない。** ページの削除と公開は投稿のスキル側の仕事で、
  どちらもユーザーの明示がいる。このスキルからは行わない
- **個人情報やお金の話が書かれたページを見つけたら、内容を写して回らない。** 見た事実だけを伝える
