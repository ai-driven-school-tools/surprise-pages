# 自分のサイトの鍵を保管する

鍵の控えを、本人だけが開ける場所へ保存します。1Password などのパスワード管理アプリを推奨します。1Password の契約や連携は、この配布物の動作条件ではありません。

## どこに保管するか

パスワード管理アプリを使う場合は、自分専用の保管庫にサイトごとのアイテムを作り、下の記録を保存します。個人用サイトの鍵を会社やチームの共有保管庫へ入れないでください。保管庫の名前だけで判断せず、誰が開けるかを確認します。

管理アプリを使わない場合は、同じ記録を `surprise-pages-keys.env` などのテキストとして、本人専用の暗号化したディスクや暗号化ファイルへ保存します。端末が故障しても取り出せる暗号化した控えを別の場所にも置き、実際に開けるか確かめます。暗号化ファイルを開く合言葉を、そのファイルと同じ場所に置かないでください。

ローカルの `.env` はコマンドが読むための作業用ファイルです。平文なので、保管用の控えは別に用意し、端末のディスク暗号化を有効にします。共有フォルダ、チャット、メール、公開の資料には置きません。

## 保管する記録の形式

サイトごとに、設定の名前と値を対にして保存します。下は形式の見本で、`<…>` は本人が取得した値に置き換えます。見本をそのまま実行用に使いません。

```dotenv
# サイトの目印
PAGES_SITE_NAME=<自分のツール名>
PAGES_SITE_URL=<https://自分のサイト>
PAGES_OWNER_EMAIL=<持ち主のGoogleメール>
# 初期設定・復旧だけで使う（サイトの通常運転には渡さない）
DATABASE_ADMIN_URL=<Neonの初期設定用接続情報>
# 通常運転（初期化が .env.setup に追記した値）
DATABASE_URL=<通常運転用接続情報>
AUTH_SECRET=<生成した乱数>
CRON_SECRET=<AUTH_SECRETとは別の乱数>
AUTH_GOOGLE_ID=<GoogleのClient ID>
AUTH_GOOGLE_SECRET=<GoogleのClient secret>
BLOB_READ_WRITE_TOKEN=<非公開Blobの鍵>
```

これと一緒に、作成日、GitHub リポジトリ、Vercel プロジェクト、Neon の保存先、Google Cloud プロジェクトと戻り先 URL を記録します。鍵を更新したら、控えも更新します。不要になった古い値は、現在の値と分かるように分けます。

Google・GitHub・Vercel などの復旧コードは、この設定とは別のアイテムに保存します。復旧コードを Vercel の環境変数やアプリの `.env` に入れません。

## 手元のファイルへ移す

設置で手元に作るファイルは `.env.setup` の 1 つです。上の記録のうち `.env.local` 向けの注記以外がそのまま入ります。

| ファイル | 入れる値 | 用途 |
|---|---|---|
| `.env.setup` | `DATABASE_ADMIN_URL` と、Vercel へ入れる 9 項目（`DATABASE_URL`・`AUTH_SECRET`・`CRON_SECRET` はコマンドが追記） | 初期化・Vercel への入力・第 3-11 章の診断・控えの作成と復元 |
| `.env.local` | 上の記録から `DATABASE_ADMIN_URL` を除いた通常運転の設定 | コードを直す人が手元で Google ログインを試すときだけ |

Neon が自動追加した初期接続の設定は、`DATABASE_URL` という同じ名前を使うため手元のファイルには入れず、保管庫の別の記録（「Neon 初期接続の控え」）に貼ります。

Mac / WSL では、作成したファイルを本人だけが読めるようにします。

```bash
chmod 600 .env.setup
```

`.env.local` を作った場合も `chmod 600 .env.local` を実行します。Windows ではファイルのプロパティで、アクセス許可を本人のみに設定します。ファイル名を変えず、リポジトリに設定されている除外が効いているか確認します。

```bash
git check-ignore .env.setup
```

各名前が表示されれば Git の対象から外れています。除外されていても、AI の指示や画面共有で内容を貼らないようにします。ファイルを AI が扱う場合も、値を応答やログへ出さないよう指示します。

投稿コマンドのログインの控えは、従来どおり `~/.config/surprise-pages-distribution/` に本人だけ読める形で保存されます。手元から投稿するときは `pages-publish login` を使い、その控えをサーバーの `.env.local` へ移しません。

## Neon の初期化と秘密の値

Neon は、役割を作るときに事前に作った SCRAM 検証子を受け付けません。そのため初期化スクリプトは、Neon の PostgreSQL 接続先に限り、機械生成した32バイトの鍵を TLS で渡します。通常運転の権限は制限したままです。他の PostgreSQL には検証子を渡します。[Neon の仕様](https://neon.com/docs/manage/roles)

Neon 側で SQL 文を記録する設定の場合、生成した鍵が記録に含まれる可能性があります。初期化の SQL 文やエラーオブジェクト全体を表示・共有しません。保存先のログへアクセスできる人も、鍵の管理者として扱ってください。
