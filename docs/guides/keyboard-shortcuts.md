# キーボードの近道（ショートカット）

ワークスペースの画面（ブラウザ・デスクトップアプリの主画面）で、キーボードだけで操作するための仕組み。

## いま使えるキー

| キー | 何が起きるか | 効く場所 |
| --- | --- | --- |
| `?` / `⌘/`（Windows は `Ctrl+/`） | キーボードショートカットの一覧を開く | どの画面でも。`⌘/` は文字を入力中でも効く |
| `/` | その画面の検索欄へ移る（入っている字は選んだ状態） | 検索欄のある画面だけ |
| `G` のあと `H` | ホームへ | どの画面でも |
| `G` のあと `M` | 自分の資料へ | どの画面でも |
| `G` のあと `F` | お気に入りへ | どの画面でも |
| `G` のあと `A` | 自分の活動へ | どの画面でも |
| `G` のあと `L` | 会社の資料へ | どの画面でも |
| `G` のあと `R` | 録音へ | 録音が使える人だけ |
| `G` のあと `S` | 個人設定へ | どの画面でも |

デスクトップアプリでは、ほかに OS のメニューが持つキー（新規ウィンドウ ⌘N・録音の取り込み ⇧⌘R・戻る ⌘[・進む ⌘]・
再読み込み ⌘R・一覧 ⌘/）が効く。これらもメニューの横に OS の作法で表示される。

## 作り

```
src/lib/workspace/keyboard-shortcuts.ts        台帳（どのキーで何が起きるか）と、照合・見せ方の純関数
        │
        ├── src/app/_components/shortcut-provider.tsx   画面全体の keydown を 1 か所で聞く。? の一覧を持つ
        ├── src/app/_components/shortcuts.tsx           useShortcut（画面が操作を結ぶ）・ShortcutKeys（キーの札）
        ├── src/app/_components/controls.tsx            IconButton の吹き出しに札を添える・SearchField が / を結ぶ
```

- **台帳に 1 行足し、使う画面で `useShortcut("名前", 操作)` を呼ぶ**。それだけで、キーが効き・`?` の一覧に出て・
  吹き出しと読み上げ（`aria-keyshortcuts`）に載る。一覧に出るのは**いまの画面で結ばれているものだけ**。
- 同じ名前を 2 つの画面が結んだら、後から結んだほう（より内側の画面）が勝つ。外れると前のものに戻る。
- アイコンだけのボタンには `shortcut="名前"` を渡す。吹き出しに名前とキーの札が並ぶ。

## 決まり（どれも「キーを横取りしない」ため）

1. **先に取られるキーに当てない。** ブラウザ・OS が先に受けるキー（⌘W・Ctrl+W・⌘T・⌘数字・⌘L など）は、ページからは
   止められないか、止めると困る。デスクトップアプリのメニューのキーも画面には届かない。一覧は検査表が持っている。
2. **修飾キーの無い近道（`/`・`?`・`G H`）は、文字を打っている間は効かせない。** 入力欄・本文の編集で字を打てなくなる。
   修飾キー付きで、台帳が `whileTyping` としたものだけ通す（いまは `⌘/` だけ）。
3. **日本語の変換の途中は何にも当てない**（`isComposing`、Safari は keyCode 229）。
4. **余計な修飾キーが混ざったら当てない。** ⌘G を `G` と読まない。
5. **字は打ち込まれた字で見る**（Dvorak の人の H は H）。ローマ字でない配列と、Option で字が化けたときだけキーの位置に落とす。
   記号は字そのもので見る（`?` は US でも JIS でも同じ字）。
6. **メニュー・一覧・ダイアログの中では何もしない**（頭文字で項目へ飛ぶ・矢印で動く、を横取りしない）。部品が自分で
   キーを使ったとき（`preventDefault` 済み）も拾わない。
7. **続けて押す形は 2 打まで・1.5 秒以内。** 1 打めの `G` は単独の近道にしない（必ず先に当たってしまう）。
   1 打めのあとに関係の無いキーが来たら、待ちを捨てて頭から見直す。
8. **押しっぱなしの繰り返しでは動かさない。**
9. **キーボードの無い画面（指で触る機械）には、札も一覧の入口も出さない。**

## 見せ方

- 札は `ShortcutKeys` ただ 1 つ（DESIGN.md 9 章「部品」）。Mac は `⇧⌘R`（OS のメニューと同じ並び）、ほかは `Ctrl Shift R`。
  環境が分かるまで（サーバーで描くとき）は何も出さない。
- 入口は 3 つ: `?`・名乗りの行のキーボードの絵（マウスの人向け）・デスクトップアプリの「ヘルプ」メニュー。

## デスクトップアプリとのつなぎ

`⌘/` はメニューが先に受けるので、メニューは主画面の window へ `SHOW_SHORTCUTS_EVENT` を 1 つ投げ、画面が一覧を開く。
合図は中身を運ばない。画面からアプリへ届く口は作らない。

## 検査

`node tests/checks/check-shortcuts.mjs`（台帳の重なり・先に取られるキー・照合・見せ方・つなぎ）。

## 次に足せるもの

- 一覧の画面での行の上下移動（`J` / `K`）と開く（`Enter`）——一覧の部品（`src/app/_components/workspace-list.tsx`）に焦点の行を持たせる
- 操作を名前で探して実行する窓（`⌘K`）——Safari と Firefox が ⌘K を検索欄に使うので、キーは別に選ぶ
- ページ本体（`/internal/…`）の道具箱との統合——あちらは本文のページの上で動くので、同じ台帳を読む別の受け口になる
