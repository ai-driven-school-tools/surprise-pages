01

なぜ HTML か

正本

正本は、1 枚の HTML。

書いたものが正本

変換の道具を挟まない。git に置けば履歴になる。

道具箱がそのまま効く

コメント・履歴・直し・書き出しが、そのまま使える。

図も表も HTML で

Tailwind・Lucide・Mermaid を額縁から配る。

「ページと同じもの」だと伝える。新しい道具を覚える必要が無いことが、いちばんの利点。

Marp と比べて

観点 Marp この形
正本 Markdown。変換が要る HTML そのもの。変換が無い
構図 型の中で組む 1280×720 に自由に置く
コメント・直し 別の仕組みが要る 既にある道具箱がそのまま
書き出し HTML・PDF・PPTX PDF と Markdown

PPTX が要る場面では Marp が勝つ。そこは隠さずに言う。

3 つの数

1280×720

枚の大きさ。器に合わせて縮め、組み替えない。

0.30

幅 390px のスマホでの倍率。構図はそのまま。

20px

枚の中の字の下限。指で広げれば読める。

数は 3 つまで。4 つ並べると、どれも覚えられない。

02

どう組むか

契約

目印は 4 つだけ。

<body data-deck>
  <main data-deck-slides>
    <section data-deck-slide>
      …
      <aside data-deck-notes>
    </section>
  </main>
</body>
  • section が 1 枚。1280×720 で組む。入れ子にしない
  • aside は話す人のメモ。枚の最後の子で、文章だけ
  • 実行部は雛形を貼るだけ。枚に script は置かない
  • 台帳に列は無い。印を見て動く

左が形、右がその意味。コードは字を 24px にして、枚の下限より上に置く。

組んでから届くまで

01

組む

1280×720 で構図を決める。手元で開けば、そのまま見える。

02

確かめる

契約と字の下限。はみ出した枚には印が付く。

03

投稿する

pages-publish で保管庫へ。版が 1 つ積まれる。

04

直す

ブラウザで直すか、原本を直して出し直す。差があれば 1 行で告げる。

軸の線は 1 本。点は 4 つ。ここが、この deck で線を引いている 2 か所目。

枚の中で守ること

  • 字は 20px 以上

    0.30 倍でも読める下限

  • vw / vh を使わない

    器の幅で組み替わると、構図が壊れる

  • fixed / sticky を使わない

    縮めた枚の外へ出てしまう

  • script を枚の中に置かない

    実行部と食い合う

  • 画像に width と height

    先に高さが要る。はみ出しを測るため

  • はみ出しは印で見せる

    保存は止めない。直すのは書いた人

6 つは validate.py が見る。ここでは理由だけ添える。

03

どう届くか

届き方

社内 /i/

  • ノートが枚の下に出る
  • コメント・履歴・ブラウザでの直し
  • 原本との差があれば 1 行で告げる

公開 /p/

  • ノートはサーバーが取り除く
  • ただの記事。道具箱は出ない
  • プレゼンと PDF はできる

「ノートは公開に出ない」は画面で消すのではなく、サーバーが配る前に取り除く。裏口が無い。

縮めるが、
組み替えない。

スマホでもパソコンと同じ構図。
足りなければ、横向きにするか、指で広げる。

1 枚目を書く。
