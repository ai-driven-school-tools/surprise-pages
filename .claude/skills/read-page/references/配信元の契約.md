# 配信元が足すと、直す材料が確実になる

`revise` は今の口だけでも動く。次の 2 つが配信元（自分のサイト のサーバー）に乗ると、
清書の原本取り寄せと、図解の断片切り出しが外れにくくなる。

この文書は契約。実装はこのリポジトリのサーバー側（`src/app/api/pages/source`・`src/app/api/comments`）。こちら（読むスキル）は
返ってきたら使う口をすでに持っている。無ければ今の探し方に落とす。

## 清書: マークダウン原本を保管する

投稿（`clean-copy`）のとき、変換前のマークダウンをページと一緒に保管する。

`GET /api/pages/source?slug=…` の JSON に、次のどちらかを足す。

```json
{
  "html": "<!DOCTYPE html>…",
  "title": "キックオフ議事録",
  "markdown": "# キックオフ議事録\n\n…"
}
```

名前は `markdown` または `sourceMarkdown`。どちらか一方でよい。空文字は「無い」と同じ。

- **公開ページ**（`/public/…`）では、リポジトリ名やパスを外に出さない。出すのは本文のマークダウンだけ
- 図解ページはこの欄を付けない（空またはキー無し）
- `revise` は切手の GitHub より先に、この欄を使う

## 図解: コメントに選択範囲の HTML を残す

人が文字を選んでコメントした瞬間の、その範囲の HTML を短く保存する。

`POST /api/comments` に `quoteHtml` を足す。`GET /api/comments` がそれを返す。

```json
{
  "quote": "注文窓口",
  "quoteContext": "API = ソフトウェアの「注文窓口」",
  "quoteHtml": "<span class=\"text-ads-accent whitespace-nowrap\">「注文窓口」</span>"
}
```

- `quote` と `quoteContext` は今どおり残す
- `quoteHtml` は短い。額縁やページ全体は入れない
- 古いコメントにキーが無くても 200 のまま。`revise` は平文の引用で本文から探す

## 作らないもの

エージェント専用に「HTML 全部＋コメント全部」を 1 枚で返す口は作らない。
それを読ませると、今と同じ無駄に戻る。
