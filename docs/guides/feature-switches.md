# 機能のスイッチの決まり

大きな機能を「コードは毎日出すが、利用者に見せる日は作る人が選ぶ」ための決まり。

- **公開**は、その日の版をまるごと利用者に出す操作。
- **機能のスイッチ**は、版の中の 1 つの機能だけを出す・止める操作。いまは環境変数で、切り替えると作り直し（再デプロイ）が要る。

大きな機能は、版は公開しつつスイッチを切っておき、準備ができた日に入れる。

## 3 つの決まり

1. **新しい機能のスイッチは切った状態で生まれる。** 環境変数が未設定なら、機能は見えない。
   コードは `process.env.PAGES_X === "on"` の形で読む（`!== "off"` の形で書くと未設定で入ってしまう）。
2. **切っていれば、元の動きが完全に保たれる。** 切ったときに通る道は、スイッチを足す前のコードそのもの。
   新しい機能の表・列・窓口を足すときも、切ったまま出して困らない形にする（DB は「足す → 移す → 縮める」）。
3. **全員に入れて安定したら、スイッチと古いコードを消す。** 台帳に書いた片付けの期限（`removeBy`）までに消す。
   消すのは環境変数の読み取り・切ったときの古い道・台帳の行・Vercel の設定の 4 つ。

## 台帳

台帳は環境変数の一覧 `src/lib/settings/environment.json` の `featureSwitch` 欄。スイッチを足す・消す PR は、この欄の更新を含める。

| 欄 | 中身 |
| --- | --- |
| `purpose`（行の欄） | 何のためのスイッチか |
| `owner` | 持ち主の GitHub のアカウント名。期限切れの知らせはこの人に届く |
| `unset` | 未設定のときの動き。新しいスイッチは必ず `off` |
| `follows` | 親のスイッチの名前（`unset` の代わりに書く）。親が切れていれば効かない補助の設定に使う |
| `removeBy` | 片付けの期限（`YYYY-MM-DD`・日本時間）。今日から 1 年以内 |
| `cleanup` | 片付けで何を消すか（どの状態になったら消すか） |

いまの台帳は次のコマンドで一覧にできる（期限切れには印が付く）。

```bash
node scripts/rules/feature-switches.mjs
```

### 例外（未設定で入るスイッチ）

`PAGES_AGENT_EDITING` と `PAGES_MOTION_EDITING` は、この決まりより前からある「全員に出したあと、止めるためだけのスイッチ」で、
未設定で入る（`unset: "on"`）。例外の一覧は `tests/checks/check-feature-switches.mjs` の `BORN_ON_EXCEPTIONS` にあり、
**減る方向にだけ動かす**。新しく足さない。期限までに、止める道を常設で残すか、スイッチを消すかを決める。

## 新しいスイッチを足す手順

1. コードで `process.env.PAGES_X === "on"` と読む。未設定・`off`・知らない値はすべて「切」として元の動きを通る。
2. `src/lib/settings/environment.json` に行を足し、`featureSwitch` に `owner`・`unset: "off"`・`removeBy`・`cleanup` を書く。
3. `pnpm check` を通す。台帳に無いスイッチ・欄の書き漏れ・未設定で入る読み方は `check-feature-switches` が赤にする。
4. 準備ができた日に Vercel の環境変数で `on` にする。問題が出たら消す（または `off`）だけで元に戻る。

## 期限切れの扱い（CI は赤にしない）

期限を過ぎても検査は赤にしない。期限切れで CI を赤にすると、関係の無い全員の PR が止まる。

代わりに、期限は人が見る。`node scripts/rules/feature-switches.mjs` が台帳のスイッチと期限を一覧にするので、直す前に確かめる。

期限を延ばすときは、延ばす理由を PR に書いて `removeBy` を書き換える（1 年より先にはできない）。

## あとで決めること

- 緊急停止を数秒でしたい機能が出てきたら、作り直しの要らない切り替え（管理画面など）を別に作る。そのときに起票する。
